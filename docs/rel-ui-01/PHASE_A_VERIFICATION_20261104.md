## 3. Pre-existing frontend failures — diagnosis (no test or app change)

| Test | Failure | Diagnosis | Classification |
|---|---|---|---|
| `services/__tests__/persistenceRcbdApi.test.ts` (whole file) | `supabaseUrl is required` at import | `src/integrations/supabase/client.ts` calls `createClient` at module load with `VITE_SUPABASE_URL`, which the vitest environment does not define. With dummy env values the file passes 1/1 | **Test-environment configuration.** Not an app defect. Fix: define test env values in `vitest.config.ts`/`src/test/setup.ts`, or mock the client. |
| `crop-protection/__tests__/navigation.test.tsx` › "appears in the workspace sidebar" | Same import error; with env set, "Crop Protection" is not found | `Layout.tsx` deliberately lists only the Early Access-verified modules (Experimental Design, Field Layout) — "Hidden modules remain in code and can return to navigation after their own validation". No other UI link reaches Crop Protection | **Stale expectation** relative to the Early Access navigation policy (plus the env issue). Restoring the menu item, or rewriting the test to assert the policy, is an **owner decision**, not a test fix. |
| `anovaDesigns.test.ts` › "reports expected combinations as a complete-design count" | Expected "if complete", got "≥4 visible in preview; full dataset checked by engine" | `buildStructuralPreview` gained `previewIsComplete` (default `false`). Its only caller, `AnovaModulePanel`, passes `true` only when the preview holds every row (`nRows`). The test omits the argument. Verified with a temporary test (deleted): the unchanged assertion passes with `previewIsComplete=true`, and the partial preview gives the intended lower-bound wording | **Stale expectation.** The app behaviour is the more conservative, correct one. |
| `designRoleIdentity.test.ts` › "makes a role swap visible…" | Expected `Rep · 3 levels`, got `Rep · ≥3 levels visible in preview` | Same cause as above | **Stale expectation.** |

Recommended test repair (not applied; none weakens an assertion):
- pass `previewIsComplete=true` where the test asserts complete-dataset wording;
- add an assertion for the partial-preview wording;
- provide Supabase test env values in vitest;
- obtain the owner's decision on Crop Protection navigation.

## 4. Reproduce

Run the backend at `bae1d0d` with
`uvicorn app_genetics:app --port 8765` from `genetics-module/`. Copy
`evidence/harness/` to `.e2e-harness/` in the frontend root and start
`VITE_API_URL=http://127.0.0.1:8765 VITE_SUPABASE_URL=http://127.0.0.1:9 VITE_SUPABASE_PUBLISHABLE_KEY=dummy npx vite --port 5173`.
Then run:
- `node evidence/run.js <out> <csv>`
- `node evidence/genetic.js <out> <csv>`
- `python evidence/check_docx.py <out> <backend>/genetics-module`
